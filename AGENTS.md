# AGENTS.md — Horizon Mods Porting Workspace

## Purpose
Port Java **Fabric** mods to **Horizon** (Minecraft: Java Edition 26.3 reimplemented in Rust) using **Horizon-Translator**.
- Horizon: https://github.com/horizon-rust/horizon
- Horizon-Translator: https://github.com/merenotnoonereal/Horizon-Translator

## Repo layout
- `<mod>-horizon/` — one folder per mod port.
  - `PORTING.md` — **source of truth** for status, what’s on/off, TODOs, limits, license, build/install steps.
  - `mixins/` — `horizon-mixin.toml` + Rust helpers/runtime generated by the translator.
  - `report/` — analysis (`report.md/json`, `translation.md`).
  - `todo/` — unmapped/missing pieces (when present).
  - `*.jar` — original mod/datapack jar used for the port.
  - `<modid>.hnmod` — present only for **full ports** ready to build/install via Horizon launcher.
- `README.md` — workspace overview and per-mod status table (keep in sync when a mod’s state changes).
- `openspec/` — SDD artifacts (`config.yaml`, `project.md`, `changes/<change>/...`).
- `.engram/config.json` — Engram project binding (`mods`).

## How to work on a port
1. **Read `PORTING.md` first**, then `report/translation.md`/`report.json` and `todo/`.
2. Classify the gap:
   - **Native/mixin/code**: unmapped targets, commented injections, untranslated logic, initializers/registries/hooks.
   - **Content/data/assets**: recipes/loot/tags/worldgen/functions/predicates/assets that require a Horizon content mod (`.hmod`) — Horizon-Translator does not generate `.hmod`.
   - **Horizon support blocker**: behavior/API not supported by Horizon 26.3 or by the pinned Horizon commit; document with evidence.
3. Make the smallest correct change. Preserve source mod behavior unless Horizon compatibility requires a **documented** difference.
4. Update `PORTING.md` and root `README.md` when status/artifacts change (e.g., `.hmod` added, `.hnmod` produced, blocker evidenced).
5. **Verification** (as applicable): file parity vs source JAR, `cargo horizon-mod check` for `.hmod` (if available), Horizon launcher `native-build` for native bundles, and runtime smoke test in Horizon 26.3. Record results.

## SDD / memory
- Complete **SDD preflight** before SDD work (execution mode, artifact store, PR strategy, review budget). Cache choices for the session.
- Planning/implementation artifacts go in `openspec/changes/<change>/` (and Engram when in `engram`/`hybrid` mode). Use `.engram/config.json` project `mods`.
- Use Engram proactively for decisions, discoveries, blockers, and session summaries when available.

## Safety & git
- Native mods run with user rights and are not sandboxed — build/install only trusted code.
- Never delete decompiled/source artifacts beyond what the tools/workflow already manage; keep provenance.
- **Do not commit, push, create PRs, or run destructive git operations without explicit user confirmation.**
- Prefer evidence-based statements: cite `PORTING.md`, file counts, tool output, or Horizon docs.
