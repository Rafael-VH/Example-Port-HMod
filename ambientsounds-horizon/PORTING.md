# AmbientSounds on Horizon

A Horizon native-mod bundle generated by horizon-port from `AmbientSounds_FABRIC_v6.3.11_mc26.3.jar`. It builds as it is and plays like vanilla: every injection that is on leaves the game unchanged until its `TODO` is filled in. 1 injections are on; 1 are written commented out in `mixins/ambientsounds/horizon-mixin.toml`, with why.

## What each part became

| Java | State | What to do |
|---|---|---|
| hook `mods` | on | The mod's row in Options > Mods. |
| @Accessor on SoundBufferLibrary.resourceManager (SoundBufferLibraryAccessor.getResourceManager) | off | No Horizon function mapped for SoundBufferLibrary.resourceManager (run `match`, or map it in a --mappings file). Notes: `todo/sound-buffer-library-accessor-get-resource-manager.rs`. |
| Java logic (classes that don't need the game) | translated 20 of 259 methods | In runtime.rs, `pub mod java`. Each method is translated whole or left out with why: report/translation.md. |

## Build it

Horizon's launcher builds a bundle folder itself (it downloads its own Rust the first time):

```bash
horizon-launcher native-build "<this folder>" --trust-native-code
```

Native mods run with your rights and aren't sandboxed: build only code you have read. `cargo test` here runs `runtime.rs`'s own tests without the game.

## Limits

- The mod's own logic that doesn't need the game is translated into `runtime.rs` (`pub mod java`): Translated 20 of 259 methods and 15 of 36 static fields to Rust. Code that uses Minecraft classes isn't: each helper lists the game calls its Java makes and what they are in Horizon. See `report/translation.md`.
- `BEFORE_CALL`, `AFTER_CALL`, `MODIFY_ARG` and `WRAP_OPERATION` select the called function by name (`selector`), with `require` counted in the target's source. horizon-mixins checks both when it plans: a mismatch fails the build with a message, it never applies silently.
- Raw targets are functions of one Horizon commit (`a46ce6898bd72016e061aaec1afc1375b384deac`): a newer Nightly may move them.
